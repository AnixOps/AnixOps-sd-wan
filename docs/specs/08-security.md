# 08. 安全规范

> 状态：草案锁定  
> 规则：安全边界优先于实现便利；未确认的安全细节不得默认为已定。

## 1. 安全目标
- 保护设备身份。
- 保护控制面身份与权限。
- 保护证书与密钥。
- 防止配置被篡改。
- 防止未授权接入。
- 防止路由与出口策略被越权修改。

## 2. 信任模型
- 客户端、边界节点、Core 节点与控制面都必须有可验证身份。
- 证书由自建 CA 体系签发。
- 证书和密钥的生命周期由控制面统一管理。

## 3. 身份与授权
- 运维人员必须走角色权限控制。
- 设备必须走实例级身份识别。
- 租户之间必须隔离。
- 高风险操作必须进入审计。

## 4. 通信保护
- 控制面与节点之间的管理通信必须加密。
- 入口协议和 Overlay 之间的职责必须分离。
- 海外 Core 只使用 WireGuard 作为内部 Overlay。

## 5. 秘钥与证书
- 证书签发、轮转、吊销、恢复都必须可追踪。
- 私钥不得明文散落在普通配置中。
- 敏感凭据必须有专门保管机制。

## 6. 审计
- 登录、授权、策略修改、证书操作、节点接入、节点退役都必须可审计。
- 审计日志必须可检索。
- 审计日志必须可按租户分割。

## 7. 日志与遥测
- 默认上报内容以网络指标、状态、错误码和诊断信息为主。
- 如需上传更细日志，必须先定义脱敏规则。
- 允许将日志和监控上报到海外控制面，但必须保持可控边界。

## 8. 供应链与发布
- 交付包必须可校验完整性。
- 发布必须支持版本追踪。
- 回滚必须可执行。

## 9. 边界风险
- 中国侧入口节点必须按抗封锁场景进行加固。
- 海外边界节点必须控制暴露面。
- 控制面必须限制管理端口与管理权限。

## 10. 风险处理原则
- 默认最小权限。
- 默认最小暴露面。
- 默认最小留存。
- 默认最小可见范围。
