# 09. Go 工程标准

> 状态：草案锁定  
> 规则：Go 工程约定优先服务跨平台交付与长期维护，不允许为短期方便破坏结构一致性。

## 1. 语言与工具链
- 主实现语言统一为 Go。
- 工具链版本在正式实现前冻结。
- 所有角色的代码必须遵循相同的基础工具链和构建规则。

## 2. 目录约定
- `cmd/`：可执行入口。
- `internal/`：仅仓库内使用的核心逻辑。
- `pkg/`：需要稳定对外复用的公共能力。
- `docs/`：正式文档与规范。
- 平台差异代码按清晰目录隔离，不允许散落到通用逻辑中。

## 3. 代码边界
- Agent、控制面、桌面 UI 的职责必须分开。
- 网络协议、策略引擎、存储、UI 和平台适配必须分层。
- UI 不得直接操作系统底层网络细节。

## 4. 错误处理
- 错误必须可追踪。
- 对外输出的错误信息必须可理解。
- 底层错误必须保留上下文。
- 不允许吞错。

## 5. 并发与取消
- 长任务必须支持上下文取消。
- goroutine 生命周期必须可控。
- 后台任务必须有退出路径。

## 6. 日志
- 日志必须结构化。
- 日志级别必须统一。
- 敏感数据不得直接输出。

## 7. 配置
- 配置必须可版本化。
- 配置必须支持默认值与覆盖值。
- 配置加载与校验必须前置。

## 8. 跨平台实现
- Linux 平台适配不得污染 Windows/macOS 代码路径。
- Windows 平台专用集成必须放入明确的隔离层。
- macOS 平台专用集成必须放入明确的隔离层。

## 9. 构建与发布
- 产物必须可重现。
- 版本信息必须可注入。
- 构建脚本必须能区分平台和架构。

## 10. 测试
- 核心逻辑必须可做单元测试。
- 平台适配必须有集成测试或等价验证。
- 协议与策略必须有回归测试。

## 11. 约束性原则
- 不为了少写代码而混用控制面与数据面。
- 不为了方便而引入 HTML 套壳桌面方案。
- 不为了短期复用而破坏跨平台结构。
