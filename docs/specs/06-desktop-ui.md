# 06. 桌面 UI

> 状态：草案锁定  
> 规则：桌面 UI 采用 Go + Fyne；禁止把 HTML 套壳作为主桌面方案。

## 1. 形态
- 桌面 UI 是客户端的操作面，不是数据面。
- 桌面 UI 与常驻 Agent 配合工作。
- 桌面 UI 需在 Linux、Windows、macOS 上提供一致的基础体验。

## 2. 技术路线
- 语言：Go。
- UI 框架：Fyne。
- 不采用 WebView/HTML 壳作为主方案。

## 3. 主要页面
- 总览
- 连接状态
- 入口档位与协议切换
- 节点列表
- 策略列表
- 诊断工具
- 日志查看
- 证书状态
- 更新状态
- 设置

## 4. 交互原则
- 信息密度高，面向运维与日常操作。
- 不做营销式页面。
- 不用夸张装饰性布局。
- 所有高频操作应可直达。

## 5. 功能边界
- UI 只负责展示与触发。
- UI 不直接改写系统路由表。
- UI 不直接承载协议栈。
- UI 通过 Agent 完成实际操作。

## 6. 状态展示
- 当前链路类型。
- 当前入口协议。
- 当前出口节点。
- RTT、丢包、抖动、UDP 可用性。
- 配置版本。
- 证书状态。
- 日志与告警摘要。

## 7. 移动端预留
- UI 的信息模型应当与手机端潜在界面可复用。
- 首版不实现手机端 UI。
