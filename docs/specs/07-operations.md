# 07. 运维规范

> 状态：草案锁定  
> 规则：运维策略、发布流程和回滚流程在正式版前必须保持可追溯。

## 1. 环境划分
- 开发环境
- 预发布环境
- 生产环境

## 2. 部署角色
- 控制面
- 中国边界入口节点
- 海外边界节点
- 海外 Core 节点
- 海外出口节点
- 客户端 Agent

## 3. 上线顺序
- 先打通中国到海外的链路。
- 再铺开海外 Core。
- 再加入多出口和智能路由。
- 最后完善企业级控制器与多租户管理。

## 4. 运行要求
- 关键节点必须具备健康检查。
- 节点状态必须定期回传。
- 控制面必须能追踪配置版本。
- 关键变更必须留审计记录。

## 5. 更新与回滚
- 客户端、边界节点和控制面都要有版本管理。
- 更新必须支持回滚。
- 更新前必须保留可恢复状态。

## 6. 备份与恢复
- 控制面数据库需要备份。
- 证书体系需要备份与恢复方案。
- 策略与配置版本需要可追溯。

## 7. 观测
- 监控指标至少包括在线率、握手成功率、RTT、丢包、抖动、切换次数和失败原因。
- 日志必须能用于排障。
- 指标和日志可以上报海外控制面。

## 8. 变更治理
- 任何会影响数据面或控制面的变更，必须先进入未决清单或变更单。
- 变更必须记录版本、影响面、回滚方式与验证结果。

## 9. 容量与扩展
- 出口池必须可扩展。
- 边界节点必须可横向增加。
- 控制面必须能随租户和节点数量增长而扩展。
