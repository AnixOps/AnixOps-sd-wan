# 04. 客户端 Agent

> 状态：草案锁定  
> 规则：客户端职责与平台边界已确认；若涉及新增平台能力，必须先进入未决清单。

## 1. 形态
- 客户端由两部分组成：
  - 常驻 Agent：负责网络能力、策略执行、链路探测、配置同步和日志上报。
  - 桌面 UI：负责状态查看、策略切换、诊断与运维操作。

## 2. 支持平台
- Linux
- Windows
- macOS
- 手机端保留后续适配可能性，但首版不做完整移动端产品。

## 3. 核心职责
- 建立和维护隧道连接。
- 执行本地策略路由。
- 识别链路类型并触发协议切换。
- 接收控制面配置下发。
- 上报运行状态、诊断数据与日志。
- 支持本地网络接入能力。

## 4. 本地网络能力
- LAN 接入。
- DHCP。
- DNS。
- 透明代理。
- 策略路由。
- 自动切换。

## 5. 平台实现边界
### 5.1 Linux
- 承担完整网关能力的优先平台。
- 使用 nftables、iproute2 等系统能力。
- 支持系统服务方式常驻。

### 5.2 Windows
- 以常驻 Agent + 桌面 UI 为主。
- 使用 Windows 服务形态常驻。
- 需要平台专用网络接入能力与系统集成层。

### 5.3 macOS
- 以常驻 Agent + 桌面 UI 为主。
- 使用 launchd 常驻。
- 需要平台专用网络接入能力与系统集成层。

## 6. Agent 与 UI 的边界
- UI 不直接承载核心网络逻辑。
- Agent 是唯一的数据面执行者。
- UI 通过本机 API 或本地通信层驱动 Agent。
- 关闭 UI 不应影响网络连接。

## 7. 配置与状态
- Agent 必须维护本地配置缓存。
- Agent 必须支持离线重连。
- Agent 必须支持安全启动后自动恢复状态。
- Agent 必须把关键变更同步给控制面。

## 8. 桌面联动
- UI 负责展示连接状态、节点、策略、日志与诊断。
- UI 负责触发连接切换和策略变更。
- UI 不直接操作底层系统路由表。

## 9. 手机端预留
- 控制面 API 必须可复用。
- 设备身份模型必须可复用。
- 策略与状态模型必须可复用。
- 不在首版中实现完整手机 UI。
