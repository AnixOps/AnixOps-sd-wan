# 05. 控制面

> 状态：草案锁定  
> 规则：控制面为自研系统；凡未在本文件确认的实现细节，必须进入未决清单。

## 1. 职责
- 维护多租户、组织、站点、设备与节点关系。
- 下发配置、策略与证书。
- 汇聚日志、指标与状态。
- 管理出口池、入口节点与边界节点。
- 驱动客户端 Agent 与边界节点的生命周期。
- 提供 Web 控制台与 API。

## 2. 技术方向
- 实现语言：Go。
- 数据存储：PostgreSQL。
- 缓存与任务协调：Redis。
- 内部服务通信：gRPC。
- 对外管理 API：HTTP/JSON。

## 3. 控制面组件
### 3.1 API 层
- 对 Web 控制台和外部自动化脚本提供接口。
- 负责认证、授权与请求路由。

### 3.2 租户与权限服务
- 负责组织、项目、角色、权限与审计对象。
- 负责多租户隔离。

### 3.3 设备与节点注册服务
- 负责客户端、边界节点、Core 节点与出口节点登记。
- 负责心跳、在线状态与能力上报。

### 3.4 策略服务
- 负责入口选择、出口选择、路由映射与策略版本管理。
- 负责把域名、IP、ASN 规则转成可分发策略。

### 3.5 证书服务
- 负责自建 CA、签发、轮转、吊销与追踪。

### 3.6 监控与日志汇聚
- 负责接收客户端和节点上报。
- 负责形成可检索的运行视图。

## 4. 多租户模型
- 租户是平台隔离的最小管理边界。
- 站点、设备、节点、策略、出口池都归属于租户作用域。
- 不同租户之间默认隔离。

## 5. 数据面与控制面分离
- 控制面不直接承载用户流量。
- 控制面只负责指挥、配置和观测。
- 数据面由 Agent、边界节点、Core 节点和出口节点承担。

## 6. 生命周期管理
- 新设备注册
- 证书签发
- 配置下发
- 在线更新
- 停用与吊销
- 重新接入

## 7. 管理界面
- Web 控制台负责人工管理。
- API 负责自动化和系统对接。
- 所有关键变更应保留审计记录。
